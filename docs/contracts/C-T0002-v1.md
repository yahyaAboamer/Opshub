# C-T0002-v1 — Qualified toolchain

Producer: T0002. Boundary: `toolchain`. Version: **v1**, 16 October 2026. Status: **ACCEPTED and frozen** (owner, 2026-10-16). Changes need C-T0002-v2.

## Boundary

| Element | Contract |
|---|---|
| Runtime | Node 24 LTS (`"engines": {"node": ">=24 <25"}`). Qualified on Node v24.16.0, npm 11.13.0, Windows 10 x64. |
| Package | `packages/toolchain-qualification/`: isolated, `private`, `"type": "module"`, own `package-lock.json` (lockfileVersion 3, every entry resolved from `registry.npmjs.org`). Not a root workspace member. Synthetic only. |
| Pinning | Every direct dependency is an exact `x.y.z` version, the lockfile root agrees with `package.json`, and `npm ci` reproduces the tree. |
| Version selection (owner decision, 2026-10-16) | Stable, non-prerelease, exactly pinned versions. Dependency risk is assessed on compatibility, security, ecosystem support and qualification evidence. There is no minimum release-age policy. |
| Server | NestJS on the standard Express adapter (`@nestjs/platform-express`, Express 5.2.1). |
| Decorator transform | Vite 8's built-in Oxc transform, configured from `tsconfig.json`. No SWC, Babel or second transformer. |
| Test runner | Vitest only. Server specs run in `node`; client specs opt into `jsdom` with a `// @vitest-environment jsdom` docblock. |
| Type safety | A separate `tsc --noEmit` lane. Vitest transpiles without type-checking. |
| Client build | `vite build` with `@vitejs/plugin-react` emits a static bundle. |

### Required settings

| Setting | Value | Why |
|---|---|---|
| `tsconfig` `experimentalDecorators` | `true` | Nest uses legacy decorators |
| `tsconfig` `emitDecoratorMetadata` | `true` | Oxc reads it from `tsconfig`. Without it `design:paramtypes` is missing, constructor dependencies resolve to `undefined` and the endpoint returns 500 (observed) |
| `tsconfig` `isolatedModules` | `true` | Matches per-file transpilation. A type used only in a decorated signature must be imported with `import type` (for example `import type { Request } from 'express'`), and an injected class must be a value import |
| `tsconfig` `module` / `moduleResolution` / `jsx` | `ESNext` / `Bundler` / `react-jsx` | Shared by `tsc`, Vite and Vitest |
| `tsconfig` `skipLibCheck` | `false` | Library declarations of these pins type-check cleanly on TypeScript 7.0.2 |
| Vitest `fsModuleCache` | `false` | Vitest 5 enables it by default and did not invalidate cached transforms after a `tsconfig` change: removing `emitDecoratorMetadata` still reported passes. With it off the same change fails |

## Test contract for consumers

**Server (DI and controller).** Build with `Test.createTestingModule({ imports: [Module] }).compile()` and resolve with `moduleRef.get(Class)`. For HTTP, `createNestApplication<NestExpressApplication>({ rawBody: true })`, `listen(0, '127.0.0.1')`, call it with Node's global `fetch` against `await app.getUrl()`, and `close()` every app in `afterEach`.

**Raw body.** With `rawBody: true`, a handler taking `@Req() req: RawBodyRequest<Request>` receives `req.rawBody` as a `Buffer` of the exact received bytes, while `@Body()` still carries the parsed JSON. Without the option `req.rawBody` is `undefined`. The qualification handler then answers 400 `raw body unavailable`. Signature checks must digest `req.rawBody`, never re-serialized JSON.

**Client.** Render with `createRoot` from `react-dom/client` inside `act` from `react`, with `globalThis.IS_REACT_ACT_ENVIRONMENT = true`, in a `jsdom` spec. No DOM testing library is qualified here. Adding one is a later, separate decision.

## Preconditions and postconditions

- **Precondition:** Node 24 on the path, and `npm ci --prefix packages/toolchain-qualification` run from the repository root (needs registry access).
- **Postcondition:** the harness passes 4/4. The installed tree equals the pins. The main typecheck has 0 errors. The negative typecheck fails with exactly one `TS2322` at `typecheck-negative/incompatible-type.ts(6,14)`. Vite emits `index.html` plus one hashed JS asset.

## Errors (harness assertion → meaning)

| Assertion | Meaning |
|---|---|
| `Node … is not Node 24` | Wrong runtime major |
| `direct dependencies differ from the qualified stack` / `… is not pinned to an exact version` | A dependency was added, removed or ranged without a contract revision |
| `lockfile resolves … differently` / `installed … differs from the pin` / `… not installed` | Lockfile drift or a stale or missing `npm ci` |
| `vitest failed` or a status other than `passed` for a named test | DI, raw-body or client behaviour regressed on the pins |
| `main typecheck failed` | A type error in qualified code |
| `typecheck accepted the intentional incompatible type` / `expected exactly one type error` | The separate type lane no longer catches errors, or extra errors appeared |
| `transpile-only run failed` | Vitest's transpile-only behaviour changed. The separation assumption must be re-qualified |
| `vite build failed` / `index.html does not reference a built script` | Client build regressed |

## Tenant and transaction assumptions

None. This boundary holds no tenant data, database or transaction. Fixtures are synthetic literals.

## Not qualified here

- Linux and CI runners. The lockfile carries the Linux, macOS and Windows native `rolldown` bindings, but only Windows x64 was executed.
- Emitting or bundling the Nest server for production, the Vite dev server and HMR, and the programmatic TypeScript compiler API. Only the `tsc` CLI was used.
- PostgreSQL/Testcontainers (T0003) and Playwright.

## Changing this contract

Changing a pin, adding a direct dependency or changing a required setting needs C-T0002-v2 under the `boundary:toolchain` lock, with the harness rerun and its evidence recorded. If a package proves incompatible, raise an ARCHITECTURE DEVIATION PROPOSAL. Don't switch frameworks or add a second test stack.
