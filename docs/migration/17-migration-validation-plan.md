# Phase 5 validation contract handoff


## Council-amended proof gates

V2 requires the independently reviewed per-scenario raw logical fixture realization manifest, KR18–KR21 clocks/quality, prior contributor amounts, MA/MB native/alias collisions and event/effect evidence—not just expected-value index arithmetic. V3/V4 require PC-C01/MP-ACQ01 closure against an independent source inventory, including authoritative removal and buffered handoff. V4/V5 add IM05 repair and MP-SEED01/RV19–RV21 inherited restrictions/privacy replay. V6–V8 require cross-class authority conflict proof and bounded traffic/approval/abort envelope.

Expected evidence must be fixed from synthetic/source facts before actual evaluation and declare shared implementation dependencies. Every critical operational hold is reviewed; discovered faulty rule expands affected-group inspection. No second production importer is requested.

These amendments preserve scope: documentation, synthetic logical contracts and static verification only. No application/provider/migration/restore experiment or Phase6 task list is executed/created.
**Purpose:** order the future evidence needed to show safe migration and correct OpsHub behavior. This is not an implementation roadmap, ticket list, engineering backlog, schedule or authorization to execute. Phase6 will turn approved architecture and these contracts into the engineering roadmap.

## Implementation-ready assertion format

Contract ID/version; approved requirement/OD/OP/A/MD linkage; fixture/source digest; environment/merchant/role/native scope; starting facts/policy/clock; ordered stimulus and fault barrier; expected canonical identities/assertions/interpretations/holds; exact KPI members/exclusions/amounts; expected provider request/effect counts; access/egress decision; durable audit/journal/privacy evidence; pass/fail/not-executed; reproducibility instructions and private evidence references.

For race tests choose alternate controlled orderings. For provider tests preserve native result/negative-evidence support. For migrations distinguish physical units/logical groups/canonical objects. For analytics include retained export generations and revision deltas. For recovery preserve independent stores across DB rollback. Do not fabricate actual execution evidence in a template.
