# OpsHub — current provider capability review

Checked 14 October 2026 using accessible official provider documentation and provider-maintained SDK/API collections. This is public-contract verification, **not authenticated pilot testing**. No credentials, tokens, live customer payloads or provider mutations were used. Linked Gentry observations remain historical evidence; they do not establish provider execution guarantees.

## Status vocabulary

- **CONFIRMED CURRENT CAPABILITY**: accessible official documentation/maintained provider artifact describes it; account access still needs qualification.
- **CONFIRMED LIMITATION**: official source explicitly restricts the capability; not an inference from missing documentation.
- **REQUIRES PILOT ACCOUNT VERIFICATION**: documented capability must be tested for actual account/scopes/side effects/response semantics.
- **NOT CURRENTLY VERIFIED**: accessible authoritative material did not establish the claim; do not convert this into “provider cannot do it.”

## Qualification result

Public evidence supports the integrated design direction: Shopify commerce/catalog/creation/cancellation/annotation, Bosta booking/status callbacks/read references, Meta period spend reports. **No connected round trip is certified.** A01/A02/A07 qualification must resolve exact account privileges, result/no-effect matching, competing booking automation and analytics policy before AC14/AC15 release. A documented capability with account gaps does not justify dropping OD08/OD09 or calling a permanent manual workflow integrated. [17](17-open-architecture-decisions.md) records containment.
