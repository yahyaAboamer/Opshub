# OpsHub — MVP threat model

**Design review**, not a security certification or penetration test. Assets: tenant/customer records, identity/grants, credentials, intent/effect reservations, evidence/audit, exports/backups and source-health signals. Trust boundaries are in 01; authorization/tenant protections in 03; effects in 06. Assume hostile authenticated users, forged provider traffic, untrusted imports and accidental/compromised worker behavior.

| Threat / attack path | Mitigation and required verification | Residual / owner |
|---|---|---|
| Cross-tenant leakage by direct ID/filter/link/join/cache/job | Checked immutable context, tenant keys/composite FKs, RLS, no global cache, separate tenant jobs; AC02 tests repeated external labels and connection reuse | Runtime arbitrary SQL/total process compromise exceeds RLS; engineering owns review/isolation tests |
| Broken access control/hidden button bypass | Server capability guards on every command/read/worker/result accept; explicit Admin authority and live auth revision | Generic routes/provider proxy forbidden; engineering |
| Platform escalation/self-grant | Separate assignment/membership, scoped admin pool/DTOs, verified recovery, no self-elevation; audit platform grants | Host/DB administrator can bypass application; restrict infrastructure accounts/MFA and audit access |
| Insecure support/impersonation | Redacted health/admin data only; no customer browsing/operational export/action override; CP DB grants exclude operational tables | Merchant-supplied diagnostics must be redacted; platform/owner policy |
| Provider token/credential exposure | Encrypted versioned secrets, worker-only decrypt, least scopes, HTTPS, no browser/job/log copies; rotate/revoke on compromise | Worker holds required tenant credentials during calls; mature crypto/infrastructure security gate |
| Webhook spoofing | Shopify raw-body HMAC; Bosta qualified authorization header and targeted authenticated read corroboration; account binding before tenant receipt | Bosta signed-event/replay contract not verified; callback is a hint where necessary |
| Webhook replay/out-of-order injection | Receipt uniqueness/object version checks, bounded ingress, late evidence policy, reconciliation; no inbound-triggered business writes | Legitimate repeated state can lack event ID; retain snapshot meaning, not invented chronology |
| Duplicate external mutation | Objective/effect reservation, immutable approved intent, one dispatch CAS, no automatic write retries, unknown blocks manual/connected paths | Independent provider actors and unqualified provider idempotency remain A01/A02 pilot risks |
| Malicious import/zip bomb/formula/parser payload | CSV-first bounded size/rows/field lengths, safe decoding, typed schema, quoted parsing, dependency-group validation, immutable preview/mapping acceptance; disable macros/archive extraction. If XLSX fallback needed, audited parser/no macro/formula execution and compressed-size limits | Pilot file limits need OP13; rejected data retains safe locator without exposure |
| CSV/formula injection | Export sanitizes strings with leading=,+,-,@ including whitespace/control prefix, intentional text encoding; validate in target spreadsheet; no formula evaluation of imported content | Numeric typed amounts preserved correctly; export engineer |
| Sensitive export theft/stale authorization | Admin explicit contact scope/step-up, requester binding, generation/download reauthorization, authenticated stream/no-store, private expiring objects | User can redistribute legitimately downloaded files; OP12 policy |
| Session theft/CSRF/login fixation | Secure HttpOnly host-only cookie, token rotation/revocation, SameSite, CSRF token+Origin, OIDC PKCE/state/nonce, exact redirect allowlist, rate limits | XSS can still act in a session; CSP/text escaping/dependency review needed |
| Stored XSS in notes/imported names | Escape text; no HTML narrative rendering; CSP and safe link handling; sanitize diagnostics | Design does not introduce rich HTML editor |
| SSRF via source/file/callback URL | Allowlisted provider HTTPS origins/account host validation; no arbitrary fetch/import URL or merchant-provided endpoint proxy; deny private/metadata hosts and unexpected redirects | Object/upload URLs generated by server; engineering |
| Secrets/PII in logs/traces/errors | Allowlist safe fields, scrub headers/bodies/URLs and provider messages; diagnostic DTOs; tests with sentinel tokens/phones | Third-party monitoring defaults must be explicitly reviewed; ops |
| Compromised provider credential | Disable affected connection/dispatch, revoke/rotate provider key, preserve prior evidence/unknown effects, reconcile unauthorized changes; notify responsible Admin through approved incident process | Revocation does not undo prior external effects; Admin/provider intervention |
| Tampered evidence/audit | Runtime append-only grants, protected revision links, correction events, backup digests/access controls; no ordinary UPDATE/DELETE on audit | DB owner/infrastructure access not cryptographically eliminated; independent backups/restricted operators |
| Resource exhaustion/noisy tenant | Upload/query/export limits, fair queue/provider budgets, timeouts, bounded connection pools, safe ingress limits | Volume envelope OP13; no massive-scale guarantee |

| Supply-chain/AI-generated code mistakes | Pinned dependencies/lockfile, review permissions and schema changes, static typing/lint, real DB/tenant/action tests, secrets scanning and CI least privilege | AI output is reviewed code, not a source of policy authority |

## Enforcement priorities

Server guards, DB roles/RLS/composite relations, action reservations, signature checks, safe imports/exports and redacted diagnostics are launch requirements. Isolated development credentials and egress controls prevent tests calling production providers. Infra admin/migration keys are not web/worker credentials. Dependency-generated schema sync is never a runtime permission.

Platform mutation requires assignment scope and explicit reason/affected-state confirmation; grant/recovery requires justified step-up. There is no general break-glass merchant override in MVP. Compromise response records who/tenant/intent/connection/time/known versus unknown effects without dumping payloads. Security/audit records have separate visibility and retention from operational debug logs.

Security tests in 14 prove architectural controls in controlled environments; they do not authorize destructive production testing or actual customer communication. Privacy/export/retention/session policy remains A04/A05/OP12. No legal compliance certification is claimed.
