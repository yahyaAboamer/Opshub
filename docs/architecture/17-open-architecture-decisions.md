## Architecture approval versus release

Architecture review can approve modular monolith, tenancy/persistence/auth/action/jobs/projection/stack proposals while marking the gates above as required qualifications. A01/A02/A03/A04/A05/A06/A07 block affected pilot release until their acceptance evidence/policies exist. A08 is a pre-release engineering compatibility check, not grounds to invent dependencies now. Missing spend inputs visibly limit analysis; they do not change analytics/ROAS MVP priority. Unknown provider mutation may require human/provider investigation, not an engineering promise of eventual automatic recovery.

Provider experiments require controlled accounts/synthetic scope and explicit later authorization for real effects. No credentials, provider calls that write, account setup, migration mapping/execution or implementation backlog is created in Phase 4. Human review of [summary](00-architecture-summary.md), ADRs, [provider matrix](18-provider-capability-review.md) and [review](19-architecture-review.md) is the next step before Phase 5.
