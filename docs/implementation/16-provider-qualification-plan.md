# Provider and compatibility qualifications

Runtime implementation homes are T0010 telemetry, T0111 Resend, T0210 Amazon S3, T0309/T0406/T0915 source reads and T0711–T0714 action transports. Predeployment T1202/T1203 use the accepted pinned runtime artifact through a controlled runner, without a nonexistent deployment prerequisite. T1211 independently qualifies production identity/account-mail configuration before shadow; no real send occurs without the exact controlled recipient envelope.

Compatibility is scheduled before consumer reliance: T0002 Nest/Vitest/decorators/raw-body; T0003 PostgreSQL17/Kysely/pg/SQL migration; T0007 exact-transaction pg-boss/grants; T0008 fake independent-record protocol; T0706 SDK/HTTP automatic-write-retry disablement; T1202 actual private Amazon S3 protection. A08/MD16 umbrella completion cannot conceal these earlier subgates.

Qualification records provider/API/client versions, account ownership/scopes, exact native identity/read/positive/terminal-negative/idempotency-lifetime contract, permitted effects, source-doc check date, actual native requests/results/effects, unknown recovery/old-sender containment, flags/disable/escalation and sanitized evidence.

Accepted task dossier is not a qualified capability. Required Q-BOOKING/Q-REPLACEMENT gates demand QUALIFIED_SUPPORTED_CORE; optional supported annotation/cancellation scopes must qualify or show exact unavailable exception. Missing safe unknown-result resolution blocks that class. A permanently manual required core cannot pass integrated readiness.

T0701 selects the first useful bounded action from actual evidence, including annotation triggers. Each later supported MVP class has T1302 enablement records. No account/API calls or compatibility prototypes were made during this planning phase; public research was unnecessary because current compatibility checks are explicitly future tasks.
