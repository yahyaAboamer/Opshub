# Decision and qualification gate map

The [canonical register](decision-gates.yaml) contains 38 protected OP/A/MD source decisions plus explicit authorization and scoped compatibility/provider/safety gates. Each task references gate ID, blocking stage, environment and capability. All unresolved decisions retain their status. Source approval is not factual/account qualification.

Before the first local task only G-P6 needs human implementation authorization; no OP/A/MD policy answer is needed to create the protected workspace. Nest/DB/queue/protocol qualifications then precede the first consumer via task dependencies and scoped START gates. Actual service procurement requires the narrow purchased-service/region portion of A05/A06; no production policy is invented.

START blocks beginning the applicable task. COMPLETION permits bounded preparation but blocks its acceptance in that scope. SHADOW, ACTION_ENABLEMENT and CUTOVER govern those actual operational boundaries and do not delay unrelated local coding. Required task acceptance alone never passes a qualification gate: review the actual capability/PASS verdict. Unsupported optional scope remains unavailable; required core booking/replacement cannot use that exception.

OP14 is a preserved future-scope boundary, not an unanswered MVP-launch choice. T1305 verifies containment; owner expansion requires a new request outside this catalog.
