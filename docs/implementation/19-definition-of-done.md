# Definition of Done

A Task is ACCEPTED only when its bounded behavior and negative cases are implemented in the permitted environment, all predecessor contracts are accepted on current main, applicable current gates pass, relevant deterministic tests have actual evidence, review findings are disposed, documentation/contracts updated and the integration owner merges the reviewed change. Record exact base/head/main revisions, input/fixture/policy/tool versions, commands/results, native request/effect/start counts for safety work, UI journey/visual evidence where applicable and recovery/disable limits. NOT_STARTED tasks retain empty actual completion evidence.

Task acceptance never supplies an owner decision, provider capability or operational permission by implication. A qualification dossier may be accepted as complete with its capability unavailable; corresponding required-core release gate remains blocked. Owner/operational tasks are signed by their actual accountable authority, not a coding agent.

A Milestone is Done only when its manifest task set is accepted, demonstrated actor journey matches [roadmap](03-milestone-roadmap.md), relevant golden/tenant/security suites pass, no severity-blocking defect remains, docs/evidence and applicable milestone-stage decisions are current, and rollback/disable behavior is proven. Local synthetic milestone evidence does not claim real integrated readiness. A milestone containing actual qualification/release work remains incomplete while that evidence/authorization is missing.

Blocking defects include any unexplained leakage/unauthorized start/blind repeat/silent input loss/fabrication/invalid active association/contributor mismatch/restored access before authority-privacy gates. They cannot receive a pilot percentage tolerance. Unknown historical facts may remain explicitly accounted/held in a signed scope; uncertainty cannot silently become trusted truth.

Implementation completion does not authorize production shadow, first action, broader actions, real contacts or cutover. Those are distinct signed boundaries in [release gates](21-release-gates.md).
