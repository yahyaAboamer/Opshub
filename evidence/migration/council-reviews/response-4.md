# Independent migration design review

**Verdict: conditional approval of the design, with three bounded amendments. No execution readiness is established.** The first draft derives safety from the right invariants: accepted identities have verified namespaces; uncertainty does not become truth; source units are conserved; KPI equality requires identical contributors; action authority is exclusive; possibly executed effects remain reserved; and restore cannot reopen access before current authority and privacy are recovered. Preserve those constraints. The remaining OP/A/MD decisions and actual implementation/provider evidence still block their corresponding rollout stages.

This review covers the original first draft of docs/migration/00–17, evidence/migration/golden-contracts.json, approved OD01–OD09, and the referenced data, analytics, effect, integration, tenancy, privacy and recovery contracts. It excludes subsequent amendments and other council responses. These are design findings, not observed application defects.

1. **P1 — Completed privacy dispositions must also fence later intake and replay.**  
   **Sections:** migration/03 MP02–MP11 and corrected re-import; migration/15 PV08/cleanup; architecture/11 provider data requests; architecture/13 restored privacy gate.  
   **Gap:** the first draft explicitly replays redactions after database restore and invalidates approval when privacy changes during staging. It does not explicitly require ordinary sync, historical backfill, identical-snapshot replay, or a corrected mapping run to consult completed source-scoped privacy dispositions before storing or publishing the same identifying fields again. A valid native identity and otherwise reproducible import can therefore recreate data that the privacy workflow already removed.  
   **Correction:** add a privacy-disposition revision to intake/selection/publication eligibility. Check the approved target/field/effective scope before materializing protected data and again before publication/export; a concurrent privacy change invalidates the candidate. Preserve only policy-permitted minimized reservation knowledge. Add a synthetic test: redact a subject, then repeat the original snapshot, import an older overlapping capture, receive a later source update, and race re-import against redaction. Protected fields remain inaccessible and excluded from new stored outputs in every path. MD14 must define whether later lawful reacquisition is permitted; no identity guess or blanket permanent ban is implied.

2. **P2 — Complete the exact golden expectations where aggregate-only declarations remain.**  
   **Sections:** migration/06 envelope/scenario catalog; migration/07 result assertion envelope and KR16; golden-contracts.json partial_attribution, spend_revision, required_scenarios.  
   **Gap:** the baseline count metrics and baseline ROAS have real contributor sets, so the suite is stronger than scalar-only regression. However, GD31 declares attributed 15,000/unattributed 5,000 without the expected attributed amount per revenue item. KR16 declares prior sales/units/delivery 3/4 without naming the prior item/shipment sets. The JSON lists all 36 scenario IDs, but that list alone supplies neither their input deltas nor their exact expected outputs. Two different wrong allocations can preserve the same total and ratio; the stated per-member assertion contract cannot adjudicate them.  
   **Correction:** specify scoped logical facts and exact per-member amounts/exclusions for these cases and every scenario that changes membership or allocation. Include the actual competing MB objects/MA alias values for identity scenarios, rather than only a list of reused alias labels. Either complete the machine-readable contract or explicitly identify the authoritative companion fixture contract. Add negative expectations for equal totals with wrong monetary contributors and equal prior-period ratios with wrong members. The documentary checker must distinguish ID presence, complete expected specification, and executed engine evidence.

3. **P2 — Prove acquisition completeness while provider listings change.**  
   **Sections:** migration/03 MP01/MRUN01; migration/08 PC-S02/S03, PC-B04 and PC-M02/M07; migration/13 CT01-D; architecture/05 inbox/checkpoint/replay.  
   **Gap:** fixed upper bounds, overlapping sweeps and page accounting are appropriate requirements. Exhausting every returned cursor still does not itself prove that every eligible source object was visited when objects enter, leave, or move across a provider's ordered listing during traversal. A run can account for every captured row while never having captured a missing obligation. The first draft does not name an adversarial traversal contract that distinguishes this case from complete coverage.  
   **Correction:** qualify each provider's ordering, filters, cursor/restart behavior and deletion/unavailability evidence. Test an object changing before its page is read, crossing the boundary between pages, appearing during acquisition, and becoming unavailable before the next sweep; include nested line pagination and interrupted restart. Require independently verified convergence to the known controlled population, or a documented incomplete/held result. The final-sync report must cite that qualified coverage method and catch-up watermark, rather than treating terminal cursor plus row conservation as sufficient proof.

**What I would retain without amendment:** the native/account identity rule and prohibition on descriptive merges; distinct original assertions, selected interpretations and legacy outputs; exact baseline KPI members; historical mistakes as explained/untrusted oracle results; contact budgets surviving reopen and restore; provider unknown-result holds; one normal booking authority including native automation; shadow egress enforcement; realistic separation of application, interpretation, authority and business remediation; independent current-grant/privacy recovery gates. None of these is an executed proof, and the documents correctly say so.

**Assumptions:** Phases 1–4 are approved as instructed; OD01–OD09 remain fixed; residual OP/A/MD choices are unresolved; the future implementation enforces the specified server/worker/database/storage boundaries; and the pilot account's actual capability and history remain unqualified. This review does not certify factual source completeness or provider behavior.

**Strongest objection to this verdict:** the draft already makes fixture realization and provider qualification future release gates, so findings 2–3 can be resolved during those stages without rejecting the migration strategy. I agree. They warrant precise acceptance-contract amendments, not redesign. Finding 1 deserves an explicit invariant now because restore-only privacy replay does not cover ordinary reimport. With these amendments and the existing approval boundaries intact, the package is suitable for human design review; it is not permission for migration, provider writes, production shadow, cutover, or infrastructure work.
